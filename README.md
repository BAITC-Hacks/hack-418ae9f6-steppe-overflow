# Steppe Overflow — Agentic AI прогноз выработки ВЭС

> 🚧 Проект в разработке. README описывает только то, что уже реализовано и проверено.

## Кратко

Прогноз почасовой выработки ветроэлектростанции из двух турбин (Алматинская область, 43.64° с. ш., 78.54° в. д.) на следующие 24–48 часов.

Кому это нужно: оператору ВЭС и диспетчеру. Выработка ветра нестабильна, а график поставки в энергосистему нужно заявить заранее, за сутки. Ошибка прогноза оборачивается штрафами за небаланс и неэффективным планированием.

Главное требование задачи — честная ретроспектива. Прогноз на каждый день тестового периода (февраль 2026) строится только по тем прогнозам погоды, которые уже были опубликованы на момент прогноза. Фактическая погода, ставшая известной позже, не используется.

## Что реализовано

- **Данные турбин (SCADA).** 10-минутные записи загружаются, время переводится из UTC+6 в UTC, помечаются простои и ограничения мощности, данные агрегируются по часам: по каждой турбине и по ВЭС в целом.
- **Архив прогнозов погоды.** Скачан из Open-Meteo и лежит в репозитории, поэтому интернет для проверки не нужен:
  - 2 569 отдельных прогонов ECMWF IFS с точным временем старта (с 15.03.2024);
  - прогнозы ECMWF 0.25°, GFS и ICON, выпущенные за 1–3 суток до нужного часа.
- **Защита от утечки будущего** — `DataStore(as_of)`:
  - отдаёт только прогоны, опубликованные к моменту прогноза, и только завершившиеся часы SCADA;
  - попытка взять более поздние данные вызывает `LeakageError`;
  - каждый прогноз сопровождается манифестом использованных источников.
- **Протокол выпусков.** Прогноз выпускается ежедневно в 14:00 (UTC+6) на 48 часов вперёд: с 00:00 следующего дня (D+1) до 23:00 дня D+2.
- **Модели для сравнения (baselines)** и эмпирическая кривая мощности.
- **Бэктест** на трёх контрольных периодах по тому же протоколу, что и тест. Метрики: MAE, RMSE, смещение, nMAE.
- **Командная строка** `windagent` и 32 автотеста.

Пока **не реализовано**: основная ML-модель, прогноз на февраль 2026, AI-агент и веб-интерфейс (см. [Ограничения](#ограничения)).

## Как это работает

```
CSV турбин ──► SCADA: UTC, контроль качества, часы ──┐
                                                     ├─► бэктест: обучение на прошлом ─► метрики
Open-Meteo ──► кэш прогнозов ──► DataStore(as_of) ───┘        прогноз выпусков периода
                                  (только опубликованное
                                   к моменту прогноза)
```

1. Для даты выпуска D момент прогноза — D 14:00 по местному времени (08:00 UTC).
2. `DataStore` выбирает самый свежий прогон ECMWF, опубликованный к этому моменту (обычно 00Z того же дня). Для остальных моделей берётся самый свежий прогноз из уже вышедших.
3. Из прогнозов погоды строится таблица: 48 целевых часов × признаки.
4. Модель, обученная только на данных до начала периода, выдаёт прогноз мощности по каждой турбине и по ВЭС.
5. Прогноз сравнивается с фактом SCADA.

## Результаты (бэктест)

MAE прогноза нормированной мощности ВЭС (0–1, где 1 — номинал), в среднем по 48 часам каждого выпуска:

| Модель | фев 2025 | дек 2025 | янв 2026 | среднее |
|---|---|---|---|---|
| ECMWF IFS → кривая мощности по анемометру турбин | 0.174 | 0.215 | 0.163 | **0.184** |
| ECMWF IFS → кривая, обученная на прогнозах | 0.186 | 0.211 | 0.183 | 0.193 |
| ECMWF 0.25° (Previous Runs) → обученная кривая | 0.218 | 0.218 | 0.217 | 0.217 |
| ICON (Previous Runs) → обученная кривая | 0.204 | 0.225 | 0.225 | 0.218 |
| GFS (Previous Runs) → обученная кривая | 0.282 | 0.234 | 0.254 | 0.257 |
| Климатология (среднее по месяцу и часу) | 0.326 | 0.353 | 0.304 | 0.328 |

Прогноз по погодным данным снижает ошибку на ~44% относительно климатологии. Эти модели — точки отсчёта для основной модели.

## Технологии

- **Python 3.12**, менеджер окружения [uv](https://docs.astral.sh/uv/)
- **pandas, numpy, pyarrow** — обработка данных, хранение в Parquet
- **scikit-learn** — изотоническая регрессия для кривой мощности
- **httpx** — запросы к Open-Meteo (с ограничением частоты и повторами)
- **pytest** — тесты
- **Open-Meteo API** — архивные прогнозы погоды (ECMWF IFS, ECMWF 0.25°, GFS, ICON) и реанализ ERA5

## Архитектура

| Модуль | Назначение |
|---|---|
| `windagent/data/scada.py` | загрузка CSV турбин, контроль качества, почасовая агрегация |
| `windagent/data/openmeteo.py` | HTTP-клиент Open-Meteo: Single Runs, Previous Runs, ERA5 |
| `windagent/data/weather.py` | локальный кэш прогнозов (`cache/weather/`) и его загрузка |
| `windagent/data/store.py` | `DataStore(as_of)`: единственная точка доступа к данным, защита от утечки |
| `windagent/protocol.py` | протокол выпусков: момент прогноза и целевые часы |
| `windagent/features/build.py` | таблица «выпуск × целевой час» с признаками погоды |
| `windagent/models/` | кривая мощности и модели для сравнения |
| `windagent/eval/` | метрики и бэктест |
| `windagent/cli.py` | командная строка `windagent` |
| `config/settings.yaml` | все параметры: координаты, модели погоды, задержки публикации, периоды |

## Установка и запуск

**Вариант 1 — uv (рекомендуется).** uv сам скачает Python 3.12 и точные версии библиотек из `uv.lock`.

```bash
# установка uv (macOS / Linux), если его нет:
curl -LsSf https://astral.sh/uv/install.sh | sh

git clone https://github.com/BAITC-Hacks/hack-418ae9f6-steppe-overflow.git
cd hack-418ae9f6-steppe-overflow
uv sync
```

**Вариант 2 — pip.** Нужен Python 3.12.

```bash
python3.12 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt pytest
pip install -e . --no-deps
```

Во втором варианте команды ниже запускаются без префикса `uv run`.

## Как проверить

Все шаги работают **без интернета и без API-ключей**: данные и кэш погоды уже лежат в репозитории.

```bash
# 1. Автотесты (в том числе: ни один из 28 выпусков февраля не использует данные из будущего)
uv run pytest

# 2. Сводка по данным турбин
uv run windagent data

# 3. Содержимое архива прогнозов погоды
uv run windagent weather status

# 4. Признаки по всем выпускам: история + февраль 2026 (~30 с)
uv run windagent features build

# 5. Бэктест моделей на трёх контрольных периодах: печатает таблицы метрик
uv run windagent backtest --period all
```

Ожидаемый результат шага 5 — таблицы MAE/RMSE по моделям, как в разделе «Результаты». Сводка сохраняется в `artifacts/reports/baselines.md`.

Обновить архив погоды из Open-Meteo (нужен интернет, ~20 минут; не требуется для проверки):

```bash
uv run windagent weather download --what single,previous,era5
```

## Данные и интеграции

### Данные турбин — `Dataset/`

Две турбины, 10-минутные записи с 11.03.2023 по 31.01.2026:
- время (UTC+6);
- средняя скорость ветра (м/с);
- нормализованная активная мощность (0–1);
- температура (°C).

Часовой пояс UTC+6 установлен сопоставлением с реанализом ERA5. Пропуски: 6.6% у турбины 1 (включая перерыв 18.05–17.07.2024) и 1.9% у турбины 2. Если у одной турбины нет данных, для ВЭС используется вторая.

### Прогнозы погоды — [Open-Meteo](https://open-meteo.com/) (бесплатно, без ключа)

| API | Что берём | Роль |
|---|---|---|
| [Single Runs](https://open-meteo.com/en/docs/single-runs-api) | прогоны `ecmwf_ifs` 00/06/12/18 UTC с точным временем старта | основной прогноз ветра |
| [Previous Runs](https://open-meteo.com/en/docs/previous-runs-api) | `ecmwf_ifs025`, `gfs_seamless`, `icon_seamless`: прогнозы, выпущенные 1–3 суток назад | дополнительные модели |
| [Historical Weather](https://open-meteo.com/en/docs/historical-weather-api) (ERA5) | реанализ | только анализ (проверка часового пояса); в прогнозе не используется |

Прогон считается доступным через фиксированную задержку после старта: ECMWF — 7 ч, GFS — 5 ч, ICON — 4 ч. Задержки заданы в `config/settings.yaml`.

Для Previous Runs проверено сравнением с прогонами ECMWF: значение «N суток назад» для часа V берётся из прогона, стартовавшего примерно за 24·N часов до V. Для каждого целевого часа используется минимальное N, прогон которого уже опубликован.

## Ограничения

- **В разработке:** основная ML-модель, прогноз на февраль 2026, AI-агент (полный цикл «погода → модель → анализ → пересчёт») и веб-интерфейс.
- **Отдельные прогоны ECMWF есть только с 15.03.2024.** Модели, использующие погоду, обучаются на ~22 месяцах. В марте–августе 2024 в архиве нет прогонов 06/18 UTC; на выпуски это не влияет, так как используется прогон 00 UTC.
- **Данные SCADA за февраль 2026 не предоставлены**, поэтому прогноз на тестовый период строится только по прогнозам погоды, без коррекции по свежим наблюдениям.
- **Внезапные простои и ограничения мощности** модели не предсказывают, а оценка идёт по фактической выработке.
- **Без интернета** обновить кэш погоды нельзя, но для проверки это и не требуется.
